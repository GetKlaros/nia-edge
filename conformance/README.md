# Conformance cases

These files are generated by the Nia server, which is the reference engine.
They are what the server answers for a fixed set of inputs. Do not edit them.

| File | Content | Replayed by |
| --- | --- | --- |
| `canonical.json` | The hash a call's arguments are bound to: canonical JSON, repeated keys, and the hash itself; and the text as `JSON.stringify` writes it back, keys in JavaScript's order | `canon` |
| `addresses.json` | Which addresses the egress proxy refuses as internal, and which hosts a list exempts | `internal/egress` |
| `signatures.json` | Ed25519 signatures of the server over a policy payload, good and bad, from a test seed that signs nothing real | `internal/policy` |
| `decisions.json` | Role decisions (`allow`, `require_approval`, `deny`) over several roles, in clean, tainted and exposed sessions | `internal/engine` |
| `secrets.json` | The secrets found in a text, their spans, and the text with each replaced. The values are made up | `internal/inspect` |
| `inputs.json` | What is read from a request: what is new in it (user prompts, tool outputs), and the tools whose results it carries | `internal/turn` |
| `outputs.json` | What is read from a model response, in the three APIs, as one document or as a stream: its text and tool calls, or why it is refused | `internal/turn` |
| `dispatch.json` | The inner calls of a dispatcher tool | `internal/engine` |
| `regex.json` | What JavaScript answers for a pattern on a value: `new RegExp(pattern).test(value)` | `internal/engine` |

A change of the server's behaviour regenerates the cases. They are refreshed
here with `scripts/sync-conformance.sh <directory of the server's cases>`, in
the same change as the code that makes the tests pass again.

`NIA_CONFORMANCE_DIR` makes the tests read another copy; the server's own
checks use it to try a change against this code before the copy is refreshed.
