# Conformance cases

These files are generated by the Nia server, which is the reference engine.
They are what the server answers for a fixed set of inputs. Do not edit them.

| File | Content | Replayed by |
| --- | --- | --- |
| `canonical.json` | The hash a call's arguments are bound to: canonical JSON, repeated keys, and the hash itself | `canon` |
| `decisions.json` | Role decisions (`allow`, `require_approval`, `deny`) over several roles, in clean, tainted and exposed sessions | nothing yet: the decision engine is not written here |

A change of the server's behaviour regenerates the cases. They are refreshed
here with `scripts/sync-conformance.sh <directory of the server's cases>`, in
the same change as the code that makes the tests pass again.

`NIA_CONFORMANCE_DIR` makes the tests read another copy; the server's own
checks use it to try a change against this code before the copy is refreshed.
