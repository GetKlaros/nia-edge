Second release of nia-edge, the client of Nia. It is a pre-release: it runs a real Hermes agent on Linux servers, and every part below was attacked in Nia's end-to-end test, on a new Fly machine too (kernel 6.12, cgroup v2).

**New**
- **Host actions (nia-hostd).** A root service runs only the actions of the role's catalogue, by name, with fixed programs: services, packages, copies between declared directories. It checks the signed policy itself, runs a call once, and only as the model path released it. Every action is journaled in a hash chain whose head Nia keeps.
- **Dry runs and applies on /etc.** The agent's script runs in a container without network or capability, on a copy of `/etc` where the files it may not read are decoys. Guards refuse a plan that weakens sshd, adds a root account or touches where root runs something; an apply writes the plan as the dry run left it, checks the configurations and puts the former files back if a check fails. The reviewer sees the diff of each file, checked against the plan.
- **The agent's MCP servers in containers (nia-mcp).** `install/mcp-linux.sh add <name> <image archive> -- <command>` runs a server in its own rootless container, from an image named by its ID: no network, no capability, read-only root, only its own token, which the agent no longer holds. Its way out is nia-edge's egress proxy, under its own name, so a role gives each server its hosts. A call runs once, as the model path released it; a server starts at its first call and stops when idle.
- **Trusted sources.** The egress proxy reports each connection with its target, so a role's `trusted_sources` (package registries, the agent's messaging) no longer taint every conversation.
- **Updates.** `install/update-linux.sh v0.2.0` downloads the binary of the machine, checks it against `SHA256SUMS`, replaces it and restarts the services; the key and the policy stay.

**Upgrade from 0.1.0**

Run the installer of this release once (`sudo install/linux.sh <agent user>`; an enrolled machine keeps its key): it adds nia-hostd and nia-mcp, their users and their firewall rules. Later versions: `sudo sh update-linux.sh <version>`.

A role that uses `trusted_sources` is refused whole by nia-edge 0.1.0, which then sends the arguments of each call to Nia: update the machines before publishing such a role.

**Not yet**
- A macOS installer. The macOS binaries are not signed or notarised.
- MCP servers hosted by their vendor, with the token added by nia-edge; MCP servers that need local files.

**Verify what you download**

```
sha256sum -c --ignore-missing SHA256SUMS
```

The builds are reproducible: `scripts/release.sh v0.2.0` on this tag, with Go 1.27.4, gives the same checksums.
