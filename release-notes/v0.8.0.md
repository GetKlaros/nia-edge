Eighth release of nia-edge, the client of Nia. It is a pre-release. An agent can now change a site, an app's files or its data on its machine the way it changes /etc: through a dry run you can review, applied once, and put back on request.

**New**
- **Folders outside /etc.** A role's catalogue may name directories (`host.dirs`: `/srv/www`, `/opt/app`, `/var/lib/myapp`...). A dry run layers each of them as it layers `/etc`, its files the other users cannot read are decoys, and an apply writes the plan into it, saved first and put back when anything fails. Undo puts every folder back together. A plan cannot make a file there executable, setuid or writable by everyone, nor a link pointing out of the folder: a folder holds data, not programs a service could run as root.
- **Closed folders.** Some are refused whatever a policy says, because one file there runs as root or is not the role's to change: `/`, `/usr`, `/bin`, `/sbin`, `/lib*`, `/boot`, `/root`, `/home`, `/etc` (its own rules), `/proc`, `/sys`, `/dev`, `/run`, `/tmp`, `/var/tmp`, `/var/log`, `/var/spool`, the package manager's, systemd's and nia-edge's state under `/var/lib`, and any folder that holds one (`/var`, `/var/lib`). A folder must exist and be reached without a symbolic link.
- **The inventory lists folders.** The hourly scan also reports the folders a plan may change under `/srv`, `/opt`, `/var/www` and `/var/lib`, for the console's Machine → Folders tab.

**Fixed**
- A directory of `/etc` with a setgid or sticky bit (`/etc/redis`, 2770 on Debian and Ubuntu) lost it when a dry run copied it up: the plan reported a change of mode nobody asked for, and an apply would have made it.

**Upgrade from 0.7.0**

`sudo sh update-linux.sh v0.8.0`, then `sudo nia-edge agents` once for the folders to show in the console.

Update every machine of a tenant before its policy names folders: a nia-edge 0.7.0 or older refuses such a catalogue, and with it every host action (services, packages, dry runs) on that machine. The console's review says which machines are too old before you publish.

**Not yet**
- Lists of sites fetched from a URL (URLhaus, CrowdSec).
- Governing on macOS and Windows; Codex's commands simulated inside its own sandbox.

**Verify what you download**

```
sha256sum -c --ignore-missing SHA256SUMS
```

The builds are reproducible: `scripts/release.sh v0.8.0` on this tag, with Go 1.27.4, gives the same checksums.
