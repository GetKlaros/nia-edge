First release of nia-edge, the client of Nia. It is a pre-release: it runs a real Hermes agent on a Linux server, but has not yet been tried on more machines than that.

**What it does**
- **Enrollment.** The machine enrolls with a one-time token, and its key is kept in a private file (mode 0600).
- **Local model path.** The agent's model calls go from the machine straight to its provider, with a key that stays on the machine. Nia never sees the prompts, the tool results or the model's text. Without a provider, model calls are refused.
- **Decisions on the machine.** Each proposed tool call is decided with the signed policy: Ed25519, verified against the key pinned at enrollment, and bound to this machine and a validity window. Nia receives a hash of the arguments and the decision for each state of the session. It picks the decision, holds the approvals and keeps the log. The arguments themselves go to Nia only when a reviewer must see them.
- **Full turns before release.** A turn is read whole before anything is released, in Chat Completions, Responses or Anthropic Messages, streamed or not. A refused call replaces the turn with Nia's message. A secret in what leaves is redacted, and a model answer that holds one is refused. Provider-run tools the role does not allow are removed from the request.
- **Egress proxy.** Every outbound connection is decided by the role, site categories included (request catchers, paste, file sharing, tunnels). Internal addresses are refused.
- **Linux installer.** `install/linux.sh` installs nia-edge as a systemd service with an nftables rule, so that the agent's user reaches nothing but nia-edge and its own loopback services. It then proves it with `nia-edge doctor`.
- **Hermes installer.** `install/hermes-linux.sh --from <user>` gives Hermes its own user and runs its terminal in a rootless Podman container with no network and no host directory. It takes over the provider the existing Hermes uses (the key leaves the agent's files) and gives its MCP servers the proxy.
- **OpenCode.** The `x-opencode-session` header that OpenCode Go requires is sent automatically.

**Not yet**
- A macOS installer. The macOS binaries are not signed or notarised.
- Local MCP servers.
- Detection of personal data and prompt attacks in the local model path.

**Verify what you download**

```
sha256sum -c --ignore-missing SHA256SUMS
```

The builds are reproducible: `scripts/release.sh v0.1.0` on this tag, with Go 1.27.4, gives the same checksums.
