Ninth release of nia-edge, the client of Nia. It is a pre-release. An agent can now pay from its company's vault on NEAR (testnet), within the rules the company set with its passkey, and only with a visa from Nia for each payment.

**New**
- **Payment key.** nia-edge makes the agent's NEAR payment key on the machine and keeps it in the state file; Nia gets the public key only. An admin gives the agent a testnet account holding that key from its page in the console; nia-edge learns it from Nia.
- **`pay` tool.** nia-edge serves Nia's payment tool at `http://127.0.0.1:8787/pay/mcp`; Hermes gets it as the server `nia_pay`, so the model sees `mcp__nia_pay__pay`. A payment runs only as the model proposed it and Nia allowed it, once: nia-edge prepares it in the vault, asks Nia for its visa, and authorizes it; without a visa it cancels it, and the vault's allowance goes back to the role.
- **Payment rule.** `mcp__nia_pay__pay` is a payment tool for every role: `unlisted: allow` never lets it through, the role must list it.

**Upgrade from 0.8.0**

`sudo sh update-linux.sh v0.9.0`. On a machine running Hermes (the user `hermes`, or `HERMES_USER`), the update also adds `nia_pay` to Hermes' MCP servers; restart its gateway then: `sudo -iu hermes hermes gateway restart`. Then list `mcp__nia_pay__pay` in the agent's role in the console.
